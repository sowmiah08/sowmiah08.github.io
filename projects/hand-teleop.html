Hand-guided teleoperation

Move your index finger in front of a depth camera and a 5-DOF SO-ARM101 chases it in real time. The chain is fingertip → 3D point → robot frame via a one-time AprilTag calibration → smoothing → IK, with safety rails at every stage.

Architecture

A reactive, topic-driven pipeline

RealSenseRGB + aligned depth+ CameraInfo
→
hand_tracker.pyFingertip→ /hand_pixel
→
pixel_to_3d.pyBack-project→ /hand_3d
→
transform_point.pyTF + filter→ /target_point
→
hand_chase.pyIK + safety→ SO101Follower

Once, at startup: tag_to_tf.py

AprilTag → static TF camera_optical_frame → base_link, used by transform_point.py for every target.

Why topics, not an action?

It's continuous streaming control with no "done". Actions suit discrete goals with feedback and cancellation.

Why small nodes?

Each stage can be debugged, restarted and echoed on its own. The cost is per-hop latency and no end-to-end timing owner.

Perception

Fingertip pixel → metric 3D point

HAND_TRACKER.PY
  • MediaPipe: 21 landmarks. Uses the average of tip (8) and PIP (6), since the tip alone is the noisiest point
  • EMA α = 0.7 · deadband 5 px · rate limit 0.4 s (2.5 Hz)
PIXEL_TO_3D.PY
  • Aligned depth, so pixel (u, v) means the same point in both images
  • Median of non-zero depth in a 5 px window, robust to holes and edges
Z = depth[v, u] / 1000  ·  X = (u − cx)·Z / fx  ·  Y = (v − cy)·Z / fy
Extrinsic calibration

Camera → robot, calibrated once

Tcam→base = Tcam→tag · Ttag→base

Tag pose from apriltag_ros (PnP). Ttag→base is a measured offset parameter.

  • 30 samples averaged: translations by mean, rotations by quaternion sum-and-normalise with a sign flip (q and −q are the same rotation)
  • Published as a static TF, because the arm itself occludes the tag while operating. Live re-detection would break the moment it moves
  • Trade-off: if the camera is bumped, the calibration is silently stale until restart
Filtering & control

Smooth small motions, snap to big ones

TRANSFORM_POINT.PY
  • tf2 lookup at "latest", which is fine because the transform is static
  • EMA α = 0.25 · deadband 1.5 cm
  • Reset on jumps > 0.25 m, so a re-acquired hand doesn't make the arm crawl along a path it was never asked to take
HAND_CHASE.PY · IK
  • LeRobot RobotKinematics on the URDF, targeting gripper_frame_link (TCP)
  • Position-only IK, with wrist_roll masked to protect the camera cable
  • Seeded from the measured joint state every cycle, iterated 20× per callback
Safety

Four independent safety layers

HARDWARE

Servo registers set at startup: velocity 40, acceleration 15.

WORKSPACE

Hard clamp: x, y ∈ [−0.25, 0.25] m, z ∈ [0.05, 0.40] m.

PER STEP

Largest joint move capped at 25°, scaling all joints to keep the direction.

DEAD-MAN

No target for > 3 s → home. On shutdown → home, then disconnect.

Even a bad IK result is bounded

Whatever the solver returns still passes the workspace clamp and the per-step clamp, two independent layers, before it reaches the motors. The step cap also guards against near-singularity joint swings.

Honest limits · Q&A

What I'd improve

Known gaps

  • No explicit "hand lost" signal: it relies on the 3 s timeout
  • Tag-to-base rotation assumed zero
  • cv2.imshow in the callback blocks a headless deployment
  • A second hand entering the frame can steal tracking

Next

  • One Kalman filter with a velocity model, instead of three ad hoc filters
  • An explicit hand-lost message and plausibility checks on Z
  • Calibrate the tag rotation, or run full hand-eye calibration
  • A headless mode without GUI calls
