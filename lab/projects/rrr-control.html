RRR end-effector control

Completed · internship challenge

A 3-DOF planar RRR (revolute-revolute-revolute) arm tracks a moving target in 2D space, using closed-form inverse kinematics, PID joint control and optional obstacle avoidance with a repulsive force field.

02 / HOW IT WORKS

Target → IK → PID → joints

Moving target

_setup_trajectory() defines the target path (x, y) = (2L, L·sin(2πft)). The robot is held for 2 seconds at the start so it follows the target instead of overlapping it, then tracks the most recent target position.

Closed-form inverse kinematics

_ik_rrr_all() computes every possible joint configuration for the target end-effector position. The trigonometric solution gives more than one answer.

PID joint control

P corrects the current error, I (theta_integral) removes steady-state error, and D (theta_derivative) damps the rate of change. Together they avoid overshoot and give a smooth trajectory.

Obstacle repulsion (optional)

_obstacle_repulsion() keeps a safe zone of twice the obstacle radius. Targets inside it are pushed out to the boundary, and the push gets stronger the closer they are.

03 / DESIGN CHOICES

Reading the brief carefully

01Why IK

The task says the end-effector must track the target using only the target's position data. Inverse kinematics maps a Cartesian position directly to joint angles, so it's the right tool.

02Why PID on top

Jumping straight to the IK solution makes the motion jerky. PID on the joints smooths the motion and reduces error over time.

03Two rates tested

Task A moves the target at 30 Hz. Task B uses a 5 Hz target with a 50 Hz control loop. Both run side by side in the animation.

04Obstacle placement

The obstacle position given in the brief, (L, 0.5L), sits off the path the robot actually follows, so it would never interact with it. I moved it to (2.0, 0.35) with radius 0.125 so the avoidance can be shown.

04 / HOW I EXPLAIN IT

Talking points

"An internship control challenge: make a 3-link planar arm's end-effector follow a moving target. I solve the IK in closed form for every joint configuration, and use a PID loop on the joints so the motion is smooth instead of jumpy. For the optional part, I added a repulsive force field that pushes the target out of a safe zone around an obstacle. The whole thing runs in Docker with one command."

// 30-second pitch

1 · WHERE

Target path gives the desired (x, y).

2 · HOW

Closed-form IK → joint angles. PID smooths the motion.

3 · SAFE

Repulsion field keeps the end-effector out of the obstacle zone.

A 3-link planar arm has multiple IK solutions. What do you do?

_ik_rrr_all() returns all the closed-form configurations instead of just one. Jumping between solutions would make the arm clumsy, so the PID loop on the joints keeps the motion smooth and the error shrinking over time.

What does each PID term do here?

P reacts to the current joint error, I accumulates error to remove steady-state offset, and D reacts to how fast the error changes, which damps overshoot.

How does the obstacle avoidance work?

It's a potential-field idea. Around the obstacle there's a safe zone of twice its radius. If the target falls inside, it's pushed outward, more strongly the closer it is, so the end-effector goes around instead of through.

Why did you change the obstacle position?

At the position given in the brief, the obstacle was off the path the arm follows, so the avoidance would never trigger. I moved it to (2.0, 0.35) so the behaviour can actually be demonstrated, and documented why.
